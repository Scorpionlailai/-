## 预先固定的两项条件

- A：原单轮T→V→H，检索query和检索配对监督改为训练集全局标准化尺度，与库中raw patch生成key的尺度一致。H仍读取16点patch、仍选四个候选、阈值0.7。
- B：A基础上，H query及库成员key使用48点输入，即目标16点+左16点+右16点；上下文只来自同一个训练窗口真实可见坐标，保存原mask，缺失和越界位置零填充。完全缺失的目标patch在上下文存在可见值时可以检索。库raw patch仍必须完整可见，仍输出四个16点候选供原H消息模块处理。

原在线库group_capacity16、max_groups128/变量、group_threshold0.8、EMA decay0.99、每epoch快照、首次可见身份去重、FIFO淘汰均保持原设置。B增加成员context_values/context_mask，重建key和序列化均保留上下文。成员资格没有放宽为使用缺失真值。B候选必须满足其全部已观测上下文的最晚时间≤query patch起点，训练边界、变量一致性、原mask和原观测值钳制均检查。

真实bank预检发现旧key在加载时会重复float64单位化，个别key发生约机器精度的字节变化，导致snapshot hash不同；已单位化key保留原字节，配有保存/加载SHA回归检查。此改动用于A/B共同的精确保存，不改变有效检索尺度。

训练监督的clean context可以读取训练真值，仅用于检索配对/对比损失；库和推理query均不读取这些隐藏真值。B检索编码器为48点输入的同类MLP，输出仍64维，额外初始化隔离RNG，保证原T/V/路由/解码器及预测头初始化一致。

这两个条件检验整体检索方案；B对A同时改变上下文输入、上下文分组及全缺失patch资格，不能将增益单独归因其中一项。未加入生成值query、多轮、更多候选或历史水平校准。
