# E23 v30：多层独立参数与并行完整三专家

日期：2026-10-03，Asia/Shanghai。

状态：用户已同意尝试“4层×8组×每组64维”，并于2026-10-03确认本文书面设计。具体实现计划等待审阅；尚未实现或训练。

## 1. 目标与设计依据

用户所说的重复同时包括串行堆叠和并行建模。目标是增加修复模块的独立建模容量，提高缺失回溯窗口下的预测准确性；训练速度可以让位于准确性，必须继续报告完整耗时与峰值显存。修复输出为64维，使用现有宽度16的PatchTST预测接口。

当前v29-r1修复模块为135321参数，三组测试平均预测MSE/MAE为0.4101210382970462/0.4238632206473491；T1为0.4022734339995899/0.4255077249609154。v29-r1的固定验证预测MSE/MAE为0.7499365438950035/0.5840456761470457。

v29-r3重复执行同一套专家参数。旧v23/v24/v25增加了候选注意力和路由投影，但仍共享H/V/T候选消息编码网络，且使用修正前的Stage1窗口尺度。因此，现有实验不足以判断多层、多组完整专家在正确损失尺度下是否有效。本轮不预先认定容量不足就是当前MSE差距的原因。

首轮实验检验三个方向：1层8组的并行容量、4层1组的独立层深度、4层8组的组合。各实验的损失、训练轮数和候选政策保持统一，使结构差异可解释。

## 2. 数据流与张量接口

ETTh1 P4：回溯96，预测96，7变量，patch16/stride8，12个patch，修复状态D=64。初始编码共享一次，输入为原可见patch值和原观察掩码：

`z0 = base_encoder([visible_values, observed_mask])`，形状`[B,C,N,64]`。

每层的G组同时读取同一个层输入`z[l-1]`。每组拥有完整的T→V→H处理单元，复用v29-r1的单次处理语义；组之间没有先后依赖。每组输出一个64维修正`delta[l,g]`以及none/H/V/T路由信息，层内融合得到`z[l]`，再进入下一层。四层使用不同参数。

```mermaid
flowchart LR
  A[可见回溯窗口与原掩码] --> B[共享初始编码 64维]
  B --> C[第1层：8组独立 T→V→H]
  C --> D[组间融合与残差 64维]
  D --> E[第2至4层：独立参数，同样结构]
  E --> F[共享修复解码器]
  F --> G[观测值保留与patch聚合]
  G --> H[现有PatchTST预测接口]
```

组内沿用v29的T预更新→V预更新→H条件消息→最终仲裁。预更新只用于下游条件计算，组输出的最终修正相对本层原输入计算，不能把预更新重复写入。每组仅执行一次，不再套用共享参数三轮控制器。

所有层的状态连接保留梯度。正式修复仅在最后一层解码一次，预测头也只使用最后一层的修复结果。逐层解码和预测用于固定权重验证诊断。

## 3. 参数独立与共享的边界

每一对`(层,组)`独立拥有：

- H的候选消息编码、质量编码、当前状态与候选匹配参数。
- V的来源/目标变量嵌入、消息与质量编码、状态匹配及来源状态投影。
- T的可见来源编码、query/key、消息与质量编码、来源状态投影。
- none/H/V/T的残差变换、打分、尺度与条件嵌入。

这些参数必须是不同对象、独立初始化，不能通过浅拷贝共享张量。H/V/T仍是三类证据，每组分别学习加工这些证据的网络；增加组数并不增加新的数据来源。

全模型共享：初始编码器、原始patch/观察掩码/validity、query mean/std、历史检索key编码器及其EMA/冻结快照、历史原型库与索引、最终修复解码器、现有预测器。

各层拥有自己的组间融合网络。共享历史检索前端不包含各组的H候选消息编码网络。

## 4. 候选读取与缓存

### H

原可见查询下的历史检索每个forward执行一次，复用现有one_group、top4、阈值0.7、时间排除规则。缓存raw候选、有效性、可见误差、key similarity、时间与支持度；每组独立编码、根据当前状态匹配并加权同一批raw候选。

检索候选身份不随层或组改变。H状态匹配保持v29的有界修正和零影响初始化。本轮增加H处理容量，不扩大候选数或阈值范围。

### V

原可见值、局部覆盖与一致性等无参数统计可以共享；每组的变量嵌入独立，因此每组须用自己的变量关系选择四个来源。仍采用window_context_topk_v1、offsets(-1,0,1)，不能拿某一组的learned prior或top4缓存替代其他组的选择。

每组的来源选择按原可见窗口完成，保留当前训练epoch下原exploration规则；各组的消息、状态匹配及质量计算独立。缓存不能跨forward或跨optimizer step复用。

### T

原可见值、掩码、位置及方向band几何共享。每组独立编码可见来源，再用自己的query/key和本层状态选择、加工各band来源。保持local_radius2和boundaries(2,4,8,16)，来源资格由原掩码决定。

缓存中的训练输入保持必要的计算图；detached provenance只用于诊断。层、组并行计算优先沿显式组维度实现；须用独立模块的参考实现验证输出和梯度，不能为了批量计算重新共享各组权重。

## 5. 组间融合、归一化与残差

G=8时，每个组产生`delta[g]`、四项路由权重及有效性。每层的门控输入为：`LN(z)`、`LN(delta[g])`、四项路由权重、rho、`log1p(rms(delta[g]))`，共134维。使用134→64→1的GELU网络，各层独立，层内各组共用该打分函数；另有每组独立bias和一个基于`[LN(z),rho]`的65→1 no-change打分。

无有效证据的组不能被门控选中；no-change始终可用。G+1项softmax得到`a0,a1,...,aG`。组打分末层、组bias及no-change打分零初始化，初始为所有有效选择的均匀权重。

将`a[g]*delta[g]`按固定组序拼接，再用每层独立的无bias线性投影`W_f: G*64→64`融合：

`z_next = z + W_f(concat(a[g]*delta[g]))`。

`W_f`初始各64列块为单位阵，使初始融合等于门控加权残差和，训练后允许不同组的不同特征被重新组合。no-change对应零修正。沿用各专家和路由器已有的LayerNorm，组间门控也使用归一化特征；不在残差写回后强制归一化整个状态。

G=1时，直接使用该组输出，省略新增组间门控与投影。这样1层1组可以与v29-r1做数值对照，4层1组也不会额外混入组间融合因素。组数为8时每组仍是完整64维，不切成8维子空间。

门控权重用于描述选择行为，不能直接解释为校准后的置信概率或对未来预测的因果贡献。不同初始化不保证不同组一定学到互补信息，需要诊断验证。

## 6. 观测锚点、specialist exposure与关闭分支

- 原观察掩码、validity、rho和query mean/std在所有层/组中固定。生成状态不会变成真实观测，也不会写入历史库。
- 隐藏及padding值在初始编码与可见统计前掩蔽。fully observed patch的状态始终精确等于原base；最后显式修复精确保留原可见坐标。
- 每层所有组均无有效专家时保持该层输入。全程无证据时返回原base；padding不参与损失、统计或预测输入。
- Stage1 specialist exposure为0.2，每个forward按各分支原候选可用性的并集抽样一次。同一目标patch在所有层/组使用同一个允许专家类型集合，不能逐组分别抽样后使H/V/T重新全部出现。
- singleton目标的T/V来源状态条件化必须回退到原可见编码/原来源信息，防止其他专家经邻居状态泄漏；本目标先前层状态只能包含其允许类型的更新。
- 专家或组关闭须在预更新、来源状态消息、仲裁和组门控的整个数据流生效。固定权重关闭诊断不等同于重新训练的消融。

## 7. 历史库与两阶段训练

Stage1历史key训练、EMA、快照更新和原型库写入均由一个共享前端负责，按原时间顺序每训练batch执行原定更新次数。不能每组重复写入同一批原型，或重复更新EMA。

Stage2读取各自Stage1选定的库、key与修复参数，冻结key和原型库，微调修复网络及现有预测器。各模型的两个阶段均从头完成，不能用已训练单轮版额外训练多组版来替代本轮公平比较。

首轮固定损失：

- Stage1：最后一层的全局缺失坐标修复MSE+0.1 retrieval loss；按固定验证全局修复MSE选权重。retrieval loss计算一次，不按组数乘倍。
- Stage2：最后一层未来预测MSE+0.2 MAE；按原固定验证MAE选权重，精确相等时取较早训练epoch。

本轮先保持现有任务损失，仅调整结构容量。逐层辅助监督、修复保持损失、组多样性损失、额外预测头属于后续可独立检验的变化，不混入这三个首轮实验。

三个模型都运行Stage1/Stage2各100训练epoch，seed2021，batch128，FP32，lr分别0.001/0.0001，weight_decay0。使用相同的数据顺序和动态训练mask规则，验证仍使用原固定mask。

## 9. 实验顺序、测试与判定

按以下顺序串行运行，避免GPU并发影响资源记录：

| 标签 | 层×组 | 作用 |
|---|---|---|
| v29-r1既有记录 | 1×1 | 当前单轮参考；重放，不重新训练 |
| v30-l1-g8 | 1×8 | 完整独立组的并行容量 |
| v30-l4-g1 | 4×1 | 独立参数的层深度 |
| v30-l4-g8 | 4×8 | 目标组合结构 |

v28、T1及v29-r3使用已有记录，不重新训练。各新模型先完成训练，锁定原固定验证MAE选定checkpoint，重放并核对身份。全部新checkpoint锁定后，三个模型各对已有三组test mask执行一次评估，seed为2021、2026100201、2026100202；同一权重报告平均MSE/MAE及位置间总体标准差。

实验矩阵及其全部结果一并报告，不根据测试结果重新选择epoch、移除组、截断层或调整配置。后续新试验仍在训练/验证数据上设计，既有三组测试用于共同评估。

验证上“同时改善单轮版”的条件为MSE严格低于0.7499365438950035且MAE不高于0.5840456761470457。若多个满足，以验证MAE、MSE、较少参数数、固定实验顺序依次排序；若均不满足，报告本轮未在验证上同时改善单轮版。另单独记录是否满足原v28门槛(MSE≤0.7402293330687785且MAE<0.5855096656989619)，不更改旧v29的validation_selection.json。

测试上是否超过T1同时列出两项指标，不只据MAE宣称全面超过。一次训练的三组缺失位置不是三个训练种子。1×8与4×1参数预算不同，比较不能单独证明并行优于串行；4×8相对1×8/4×1分别检验增加层数/组数的效果。

## 10. 必要验证与诊断

实现前后至少验证：

1. 所有层/组独立参数对象；独立初始化；选定真实数据上的有限梯度进入各分支及融合投影。
2. 1×1显式参数映射后与v29-r1输出对照；旧v3/v12/v28/v29真实checkpoint严格加载，既有v29-r1固定验证预测指标重放至1e-6。
3. T→V→H条件传递、不重复写回、后层读前层状态；修改某组权重不会修改其他组参数。
4. 组维批量计算与独立参考的输出/梯度对照；门控有效性与无证据回退；禁用组/专家不经预更新或来源状态泄漏。
5. 原观察值保留、隐藏输入不变性、padding无影响、specialist exposure跨组/层一致、全局尺度评分。
6. 每forward一次H检索；每batch一次历史写入/EMA；Stage2重放前后bank/key SHA保持一致。
7. 小型两阶段端到端训练、checkpoint身份拒绝错配、真实CUDA batch128 forward/backward及资源预检。
8. 完整训练后重放全部固定验证窗口，核对权重SHA、指标及历史状态，再开始三组测试。

各选定checkpoint验证诊断：每层修复MSE/MAE、预测MSE/MAE、状态更新RMS；每组路由及组门控分布；组输出差异与固定权重关闭单组后的预测变化。只有诊断输出经过同一原decoder/预测器，不能把中间层临时改成正式模型。
