# E23 v3 Targeted Accuracy Iterations: Loss, Contextual V, H Rerank

Date: 2026-09-30. The user selected directions 1, 3 and 4 from the post-v10 review, in that order. The goal is lower forecast MAE than E23 v3 without giving up its validation MSE, and ultimately a defensible accuracy result against SAITS. The PatchTST predictor architecture and width 16 remain fixed. The selected v3 checkpoint, E22/SAITS data, fixed masks, prior experiments and unrelated working-tree CSV remain immutable.

## Controlled sequence and decision rule

Run three validation trials in order. Each changes only its named mechanism relative to the current validation winner. A candidate becomes the current winner only when its selected fixed-validation MAE is strictly lower than the current winner's and its selected validation MSE is no higher than the original v3 value `0.7647695325129157`. The starting winner is v3 (`MAE 0.5904396656148828`). If a trial fails, the next starts from the unchanged winner. All comparisons use ETTh1 P4, 96→96, seven variables, patch 16/stride 8, E22 fixed validation/test masks, train-only standardization, seed 2021, batch 128, full 100 epochs per trained stage and earliest minimum validation MAE for Stage 2. After all three validation trials, at most one final non-v3 winner receives one selected ETTh1 test and fixed-input profile. If none wins, v3 remains active and no new test is run. ETTh1 has informed earlier design choices, so a test win is exploratory until checked on independent datasets/seeds.

### Trial 1: Stage 2 loss alignment (v11)

Reuse the selected v3 width-64 Stage 1 checkpoint, its frozen H memory and key state, and the exact flat H/V/T repair and width-16 PatchTST predictor. Train a fresh 100-epoch Stage 2 with `forecast MSE + 0.2 × forecast MAE` on train-standardized targets. The coefficient 0.2 is fixed before validation inspection and is not swept. Select the earliest lowest validation forecast MAE; enforce the original v3 MSE guard. The loss mode is explicit and paired in the Stage 2 manifest/checkpoint; the original `forecast_mse_only` path and old v3 loader remain exact. No new Stage 1 run is required.

### Trial 3: Window-conditioned V source choice (v12)

Keep four directed source-variable slots and three local patch offsets `{-1,0,+1}`. For each batch item, target variable and target patch, rank all six other source variables by a cheap score computed **before** the message MLP: existing learned directed relation prior + `0.5 ×` valid visible-source fraction across the local offsets + `0.5 ×` aligned observed-coordinate consistency (`exp(-mean absolute difference)` when overlap exists, zero otherwise). All input values used in the score are masked observations; hidden and padding values cannot affect it. Use stable ranking and select four sources. During Stage 1, keep the existing deterministic rotating exploration behavior by replacing the final selected slot with one unselected source; Stage 2/inference use the ranked four. Build candidate messages only for selected sources, with the existing local weights, router and explicit repair. A source with no visible local values remains invalid, and an all-invalid pool leaves V unavailable. This differs from prior global-prior-only top-k and from the failed dense forecast mixer. Add a new strict config identity for this mode. Train a fresh 100-epoch Stage 1 and Stage 2; Stage 2 uses the current winner's loss mode (mixed if v11 won, MSE otherwise).

### Trial 4: H visible-error rerank across causal groups (v13)

Keep the H message width and final candidate count at four. The existing train-only, same-variable published archive and key encoder are unchanged. For each query, take the two highest key-center-similarity **causal** groups, then the four highest-key-similarity causal members within each group (at most eight shortlisted members). Apply the existing minimum key similarity 0.7 and compute the existing query-normalized visible-coordinate error. Rerank the shortlisted members by `key_similarity − visible_error` and retain the stable top four; only those four enter message/quality/weights. Group and member ties retain the original stable order. If no eligible member exists, H is unavailable and the router can take `none`. Keep the original one-group query method exact for v3 and all prior artifacts. Add strict config and paired checkpoint identity for this mode. Train a fresh 100-epoch Stage 1 and Stage 2 on the current winner's V mode and Stage 2 loss mode.

## Verification and reporting

Before each run, prove the original v3 selected manifest/checkpoint still reconstructs. Unit tests cover mixed-loss arithmetic and gradients; loss identity tampering; V per-window/per-patch source variation, self-exclusion, deterministic ties/exploration, hidden-value and padding invariance, candidate limits and empty sources; H two-group causal/train-only guards, visible-error rerank, stable ties, fixed four slots and empty pools. Integration tests verify new config and paired Stage 1/2 identities reject cross-variant loads before evaluation batches. Run a real P4 GPU one-batch forward/backward smoke for each architecture, then full training in independent ignored roots with hashes, epoch trajectories, finite metrics and unchanged H state. Record validation MSE/MAE and candidate behavior even for negative trials. Do not rerun any prior selected test.
