## Top-p semantics

Fix `p=0.9` once for both H and V, with no validation-tuned temperature. A selected prefix contains the smallest number of ranked, eligible candidates whose cumulative softmax probability reaches or exceeds 0.9; at least one eligible candidate is retained. Stable ties use existing deterministic source order. Invalid candidates do not enter the probability denominator or cumulative sum. The selected prefix is represented by a Boolean candidate mask in the existing static tensor layout; unselected slots contribute zero to messages, quality, candidate counts and diagnostics. If no candidate is eligible, the expert remains unavailable and the router can use `none`.

**H:** Keep the existing train-only published prototype groups, same-variable restriction, 0.7 minimum key similarity and causal member cutoff. First retrieve at most eight highest-key-similarity eligible members from the one best causal group; eight is a fixed compute cap, doubled from the old four. Compute the existing visible-coordinate error and score `key_similarity − visible_error` for each retrieved member. Apply top-p to the softmax of these scores, then renormalize the existing message weights over the retained prefix. The cap protects training memory, so this is nucleus selection **within the best eight retrieved members**, not an uncapped probability calculation over all archive entries. The H group index and key encoder semantics are unchanged.

**V:** Score all six other source variables using the existing directed source/target relation prior, excluding self. Stable-sort them, softmax their six prior logits, and keep the shortest 0.9-mass prefix. For each retained source, gather the same `{-1,0,+1}` current-window patch offsets; visibility still determines candidate validity and the existing local consistency score determines final message weight. Stage 1 may append one deterministic rotating source outside the prefix for exploration, mirroring the original exploration intent; Stage 2 and inference use exactly the top-p prefix. This V remains a current-window cross-variable expert, not the historical-variable adapter tested in v6/v7.

Top-k remains the exact legacy path when top-p is absent: H maximum four members, V maximum four sources, same state keys and outputs for the original v3 manifest. The `D128/top-k` control uses precisely those legacy candidate rules. Width 128 affects the base encoder, H key and message widths, V/T message widths, router and shared decoder; it does **not** change patch geometry or forecast-head width. D128 starts a new Stage 1, because D64 H keys and model weights are incompatible.
