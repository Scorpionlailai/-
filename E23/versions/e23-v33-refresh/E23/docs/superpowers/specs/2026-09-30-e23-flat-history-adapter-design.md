# E23 Flat H/V/T with an Optional Historical-Variable Adapter

Date: 2026-09-30. The user chose to revert the unsuccessful two-group architecture and continue improving the existing E23. The active baseline is the selected width-64, flat H/V/T v3 checkpoint: fixed-validation MSE `0.7647695325129157`, MAE `0.5904396656148828`; selected ETTh1 test MSE `0.4272647293`, MAE `0.4344485763`. The grouped v5 trial worsened validation MSE/MAE to `0.7907560018`/`0.6002585104`, although removing its historical-variable leaf raised the error within that checkpoint. This motivates a controlled add-on that retains v3's trained route.

## Choice and hypothesis

Three approaches are available. Repeating the hierarchical groups changes routing and expert count together; this trial already failed. Retraining a flat four-expert router changes all arbitration weights and loses the exact v3 starting point. Choose a zero-initialized historical-variable adapter after the existing flat H/V/T router. It tests whether aligned historical cross-variable values add useful information while preserving v3 predictions exactly at initialization. This is a hypothesis; the grouped ablation does not guarantee improvement in the flat model.

## Evidence and model

Use the published, paired v3 Stage 1 H bank and frozen key, together with the selected v3 Stage 2 repair and predictor weights. Reconstruct an immutable historical archive from `protocol.standardized[:train_end]`. For each damaged target patch, H retrieves top-four target-variable historical prototypes as before. The adapter uses only valid H candidate starts and retrieves up to four other-variable patches from the archive at those exact starts. It verifies the H target prototype raw patch equals the aligned archive target patch. Each candidate must end no later than both the query's **lookback-window start** and `train_end`, preventing the training-only adapter from using clean source values inside the current lookback. This stricter cutoff makes historical evidence distinct from the current-window V/T evidence. Invalid candidates contribute zero.

The historical-variable encoder learns a separate directed source-target relation prior and projects normalized aligned source/target patches into a width-64 message. The source values use the current query's source-variable normalization statistics; H target values use target-variable statistics. The old H, V, T evidence, their specialist training history, the four-way `none,H,V,T` router, the decoder, observed-value clamping and width-16 PatchTST predictor retain their selected v3 weights. An adapter MLP maps the historical-variable message and routed latent to a correction. For each target variable, a trainable gate initialized to zero scales that correction by `0.1*tanh(gate)` and applies it only where historical-variable evidence is available and the target patch is damaged. A zero gate must produce bitwise-equal v3 repaired patches and forecasts. The adapter is optional; `none` is the default and keeps legacy model state keys/loaders unchanged.

Optimize only the historical-variable encoder, adapter MLP and variable gates with fresh Adam, learning rate `0.001`, zero weight decay, batch 128, seed 2021, 100 epochs and forecast-MSE-only loss. Select the earliest fixed-validation MAE minimum across epoch **0 through 100**. Epoch 0 is the exact v3 checkpoint; if no trained epoch improves validation MAE, the selected result is the unchanged baseline.
