# E23 Grouped Historical and Current Recovery: ETTh1 P4

Date: 2026-09-30. The user requested two evidence groups: historical H plus historical-variable V, and current-window T plus a separate current-variable V. Accuracy is the main objective; speed is secondary. This supersedes the unrun equal-ensemble idea and leaves prior v1–v4 artifacts unchanged.

## Evidence and choice

The existing V gathers originally observed values from other variables in the current 96-point window. It cannot simply be renamed historical. The sparse H prototype bank has no start shared by all seven variables and low exact-start overlap between pairs. Two viable historical V designs are (a) aggregate independently retrieved per-variable prototypes or (b) use each H target-prototype start to read aligned source-variable patches from the training-only standardized archive. Choose (b): its cross-variable values refer to the same historical time as the H match. Independent per-variable retrieval would confuse unaligned historical events. A learned relation matrix alone would not supply historical source values.

## Data and causality

P4 source, fixed masks, train-only standardization, 96/96 windows, 16/8 patches, seven variables, seed 2021 and batch 128 remain locked. The new archive is exactly `protocol.standardized[0:train_end]`, read-only and reconstructed from the source CSV whenever a model is built. Only valid H retrieved starts anchor historical V. For an H candidate at absolute start `s` and query patch start `q`, historical V may read source-variable values at `[s,s+16)` only when `s+16 <= q` and `s+16 <= train_end`. Invalid candidates contribute exactly zero. No forecast target, validation or test value is in the archive. This archive contains real train values; the per-window synthetic missing mask applies only to the query window. H's prototype bank remains the retrieval selector and its paired frozen key remains unchanged during Stage 2.

Historical V uses a separate trainable directed source-target relation prior, top four source variables per target, and H's top four candidate starts. Its message contains aligned historical source and target patches, the current target base latent, and H match confidence. Source patches are normalized with the current query's source-variable mean/std; target H patches use the target-variable mean/std. The old V implementation remains the current-window V and continues to use only originally observed source values in the current lookback. T remains unchanged.

## Two-level routing

The historical group has H and historical V; the current group has T and current V. At each damaged target patch, a leaf router scores the available experts within each group and forms one group residual. A top router chooses among `none`, `historical`, and `current`, then adds the weighted group residuals to the base latent. Empty groups have zero residual and zero top weight; when both are empty, `none` weight is exactly one and the output equals the base. Visible target coordinates remain copied from the original observations by the existing explicit repair path. Group specialist exposure during Stage 1 exposes one usable group for 20% of damaged patches, without forcing an unavailable group. Report both group and leaf availability/weights so the two dimensions can be checked empirically.

Use a new `architecture: grouped_history_current_v1` E23 config and fresh width-64 Stage 1 and Stage 2 roots. Legacy configs lacking `architecture` mean `flat_hvt_v1`; legacy checkpoint/state structures and loaders remain compatible. The E23 config hash and strict Stage 1/2 identity checks prevent accidental cross-architecture checkpoint pairing. The forecast mixer is `none`. Stage 1 uses the same 100-epoch hidden-coordinate SmoothL1 plus retrieval objective, Stage 2 uses a fresh Adam optimizer and 100-epoch forecast-MSE objective, with earliest fixed-validation MAE minimum selecting the Stage 2 checkpoint.
