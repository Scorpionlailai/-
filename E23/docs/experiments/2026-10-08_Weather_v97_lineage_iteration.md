# Weather：沿 ETTh1 v97 最佳修复路线继续迭代

## 用户约束与起点

2026-10-08 用户要求在 Weather 继续改良修复与预测，并明确以 ETTh1 中大多数修复指标优于 T1 的版本为起点。起点为 **E23-v97**；v101 是它的等价缓存执行实现，v102 提供变量数适配。此次先完成相同结构在 Weather 的迁移对照，再据固定验证诊断确定 Stage 1 改动。

ETTh1 四个场景、全窗口/近32点、MSE/MAE 共16项修复均值，v97 有15项低于 T1；唯一例外为 `sr010_bl16` 的近32点 MAE。这是相同20组开发缺失位置、单次训练结果，不是多次训练均值。依据：[逐项修复对照](E23_stage1_paired_mask_comparison_20261007.csv)、[冻结下游预测](E23_v97_frozen_prediction_20261008.csv)、[v101等价验收](2026-10-08_E23_v101_combined_validation_cache.md)。

## 本轮迁移设置

- 数据集 Weather，21变量、10分钟采样，回溯96、预测96；起点率0.10、块长8。
- 原封存数据、训练集标准化、划分、训练窗口及缺失参数不变。固定验证与20组开发测试掩码均复用 E24 `shared_protocol_v1/dataset_manifest.json`。
- 不加载 ETTh1 训练权重。粗修复初始化来自已有 **Weather同场景 v79、seed2023、100轮**权重及历史库；因此本轮是 v97 架构迁移，并复用同数据集父阶段。
- 主干保留 H/V/T、TV→H 单轮、点级路由、置信度重叠聚合、八头总64维候选读出、近32点精炼与均值校正。V仍是 v97 固定4来源，暂不继承 v103 动态来源。
- Stage 1 新增 v97 的全96点 dense 残差：64维、局部卷积、两层 Transformer，结合粗修复、真实可见值、可见掩码、边界插值残差与支持度。新增残差零初始化。
- 冻结专家主干与历史库，只训练既有均值分支和 dense 分支，共109,719参数。额外100轮、batch128、FP32、Adam `lr=1e-4`、无weight decay、seed2023。
- Stage 1 损失：全缺失位置 MSE + 0.25×近32点 MSE + 0.05×近32点 MAE。误差均在训练集全局标准化空间计算，无未来预测辅助监督；固定验证全窗口修复 MSE 选权重。
- Stage 2 修复器**完全冻结且 eval**；原 PatchTST 结构、配置、初始权重保持；纯预测 MSE、100轮、batch128、FP32、Adam `lr=1e-4`、seed2023。验证 MAE 为主，验证 MSE 另存一版。
- 锁定后两版 checkpoint 分别评估原20组掩码，报告预测、全窗口修复、近32点修复的 MSE/MAE及位置标准差。测试不参与 checkpoint 选择。

## 效率与资源口径

采用 v101 已验收的固定验证缓存：Stage 1 缓存冻结专家输出，Stage 2 缓存冻结修复器的预测输入。首次构建计入完整训练时间；训练掩码仍按原协议逐轮变化，未用固定训练掩码替换。Stage 1 初始全流程验证与缓存验证必须逐指标完全一致。

GPU0独立运行本模型，GPU1上的 E24 实验保持原安排。每300秒更新任务状态；本会话运行期间每约600秒汇报主要进度。

分别记录额外修复训练、预测训练的全部轮次、验证、保存及缓存构建时间、PyTorch allocated/reserved峰值；完整方案成本另计入复用父粗修复阶段。三条命令耗时之和不会标为一次连续冷启动实测。最终测试时间另记。

## 当前基线目标

以下均来自 Weather同场景已完成20组测试；MSE/MAE分别有不同领先模型。

| 模型 | 预测 MSE / MAE | 全窗口修复 MSE / MAE | 近32点修复 MSE / MAE |
|---|---|---|---|
| v79 Weather | 0.199519 / 0.247416 | 0.045973 / 0.067763 | 0.046785 / 0.073846 |
| v103 Weather | 0.197220 / 0.242822 | 0.044039 / 0.065166 | 0.045115 / 0.071264 |
| T1，冻结同预测接口 | 0.191598 / 0.231173 | 0.047406 / 0.064644 | 0.048624 / 0.066960 |
| SAITS，冻结同预测接口 | 0.195832 / 0.235960 | 0.046612 / 0.044156 | 0.045703 / 0.044010 |
| CoIFNet，作者原生预测 | 0.176578 / 0.220279 | 0.109619 / 0.158742 | 0.117285 / 0.169508 |

T1使用相同冻结预测接口，可用于直接检验修复模块；CoIFNet是原生预测方法，预测头不同；其修复项是原生历史重建。暂不以胜过一个模型等同全部基线领先。

## 验证诊断与后续改动依据

已有 v103 全5175个固定验证窗口诊断与模块耗时记录保存于：
`artifacts/performance/weather_iteration_20261008/`。

- 验证预测 MSE 的约52%来自 `rain (mm)`、`raining (s)`，但这只是绝对贡献，尚需与 T1 同变量差值比较才能确定应该优先修复哪里。
- 把所有缺失历史替换为真值、保持已训练预测器不变，并未改善预测 MSE。这是改变预测器输入分布的诊断，不能解释为“完美修复无用”或预测上限。
- 直接边界插值改善了验证修复 MSE，但恶化了修复 MAE与预测；不据此强制替换现有修复值。
- 单个batch的 v103 前向 profiler 显示候选点读出约占总前向 CUDA 时间46%；这不是完整训练耗时占比，也不是 v97 的实测。
- 对原 Weather 中 `-9999` 的疑似数据问题不更改 CSV、标准化或评测尺度，避免改变当前共同对照协议。

后续仅根据固定验证比较来选择 Stage 1 候选，并保留原预测头与冻结 Stage 2。先完成 v97 迁移，避免把上一版 v79 主干上的 v103 结果当作最强修复路线的迁移结论。
