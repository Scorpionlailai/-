## 1. 原始种子与后续开发种子

原E23配置与v31-B最初权重使用 **2021**。后来对照T1论文的五种子设置，独立训练102、202、302、402、502；502是这五个种子中E23-v31-B的20组测试MSE、MAE最低者，也是T1的测试MSE最低者。T1的测试MAE最低者为302，E23的验证MAE最低者也为302。

因此，“502最好”只适用于新完成的五种子测试组。该组不含2021，不能由此称502为整个项目历来最优种子。2021旧结果仅测试三组位置，与502的新20组均值不能直接用于选最优种子。依据已见测试结果选502做开发，属于探索；正式结论应报告预先约定的全部种子结果。

## 2. v41改动与当前T1对照的归因限制

v41每组均从缓存Stage1修复器和**重新初始化的预测头**开始。没有接着已训练好的Stage2预测头额外训练，没有增加预测头轮数，没有改变其学习率或结构。慢速组降低的是修复器学习率，冻结组冻结的是修复器；预测头仍按原规则从头训练100轮。

但“预测头结构相同”不足以证明整个下游训练协议完全相同。核实后的配置为：

| 项目 | T1现有P4复现 | E23-v31-B | E23-v41-tail32-slow |
|---|---|---|---|
| 预测头 | 原PatchTST D16，35,427参数 | 相同 | 相同 |
| 502预测头初始SHA | 26cee63e94dc41607f346f09a29e01cf7d02e75e513b1d9b631ce270ec3e0b7c | 相同 | 相同 |
| 预测头训练 | 从头100轮，Adam，batch128，FP32，lr=1e-4，weight decay0 | 相同 | 相同 |
| 选模 | 原固定验证MAE | 相同 | 相同 |
| 预测损失 | MSE | MSE+0.2MAE | MSE+0.2MAE |
| 修复保留损失 | 无 | 第11轮起0.05均匀缺失修复MSE | 相同 |
| 修复器Stage2更新 | 全部T1修复参数，lr=1e-4 | 原H key encoder冻结，其余lr=1e-4 | 原H key encoder冻结，其余lr=1e-5 |
| 末patch无效位置的值 | 重复末时间点 | 置0 | 置0 |

最后一行也应列入对照口径：当前预测头的数值投影会读patch数值；validity决定mask含义，但不会自动将输入的无效补齐值清零。此前的固定权重补齐干预诊断显示两模型已适应各自规则，不能仅改测试输入并把其结果当作重训后的统一协议结果。

T1原论文的主任务是插补，并没有本项目这套PatchTST Stage2。现有T1 Stage2是本项目增加的下游任务接口，统一下游预测训练不等于修改T1原生插补架构。[T1论文任务和训练说明](https://arxiv.org/html/2602.21043#A2.SS4)。

**结论修正：现有数值可以比较已定义的完整训练方案；不能把它们描述为“只替换修复模块、预测端训练完全一致”的严格对照，也不能把收益全部归因于修复架构。v41-tail32-slow通过的是相对E23-v31-B的预设验证门槛，仅作为该训练路线上的开发候选。**

证据：[v41优化器分组](/home/xyw/paper/.e23-v41-drift/E23/integrations/e23/repair_updates.py:17)、[T1原始Stage2入口](/home/xyw/paper/.e23-t1-standard/E23/scripts/run_author_aligned_p4.py:93)、[T1预测头从头初始化](/home/xyw/paper/.e23-t1-standard/E23/scripts/run_author_aligned_p4.py:314)、[补齐处理诊断](/home/xyw/paper/E23/docs/experiments/ETTh1_P4_forecast_sensitive_seed502_20261004.md)。

## 3. 当前P4中T1没有获得额外的未来修复监督

双方Stage1均调用同一个P4数据迭代器，使用同一训练分区[0,8640)、96点回溯及相同随机缺失规则。迭代器同时生成历史和未来张量，但当前双方Stage1模型及损失均只使用历史；v31-B、v40、v41复用的Stage1都没有启用辅助未来预测目标。

| 项目 | 双方当前Stage1 |
|---|---|
| 候选历史窗口 | 8449个，起点0到8448，长度96 |
| 每轮实际窗口 | 8448个；batch16和128均丢弃同一个末样本 |
| 历史窗口坐标并集 | [0,8544) |
| 预测标签坐标并集 | [96,8640)，Stage1不作为未来预测标签使用 |
| 未作为修复窗口覆盖的训练尾部 | [8544,8640)，96点 |
| 标准化拟合范围 | 双方均用完整训练分区[0,8640) |

已实测seed502第0和第1轮：batch16与128的有序窗口起点SHA、缺失mask SHA及隐藏坐标数量完全相同。完整读数见[数据审计JSON](/home/xyw/paper/E23/docs/experiments/2026-10-04_E23_T1_seed_stage2_data_audit.json)。共有标准化统计覆盖尾部96点，因此应说尾部“未作为修复监督窗口”，不能说它们完全没有被任何数据处理使用。

滑动窗口中，同一时间点在不同样本里具有不同角色。例如，历史[0,96)对应预测[96,192)；后续历史[96,192)又会将前一窗口的预测区域作为修复训练数据。故“预测标签都没有参加过Stage1修复”不成立，真正的窗口覆盖缺口是最后96点，而且双方相同。

证据：[共同窗口构造](/home/xyw/paper/.e23-t1-standard/E23/src/malr/data/windows.py:24)、[共同P4迭代器](/home/xyw/paper/.e23-t1-standard/E23/integrations/forecast_compare/protocol.py:162)、[E23修复目标](/home/xyw/paper/.e23-t1-standard/E23/integrations/e23/train.py:539)、[T1修复目标](/home/xyw/paper/.e23-t1-standard/E23/scripts/run_author_aligned_p4.py:83)。

## 4. T1训练次数确实更多，不能与独立数据量混淆

seed502下，每轮双方都使用8448个窗口。实际训练成本为：

| 项目 | E23-v31-B Stage1 | T1 Stage1 |
|---|---:|---:|
| batch | 128 | 16 |
| 实际轮数 | 100 | 136 |
| 每轮优化器更新 | 66 | 528 |
| 总优化器更新 | 6600 | 71808 |
| 累计窗口呈现次数 | 844800 | 1148928 |

T1累计窗口呈现次数是E23的1.36倍，优化器更新次数是约10.88倍；这不表示它有10.88倍独立训练数据。T1原配置最多300轮、patience30，小batch16；实际五种子轮数依次为68、100、93、88、136。当前保留作者训练配置的路线有其来源，不能在解释效率或结构优势时忽略训练预算差异。

## 5. 论文原设置与冻结发布脚本须分别说明

论文附录的数据表将ETTh1训练项列为8545，数值与只要求长度96的插补窗口数8640-96+1一致；后一个解释是按长度推算的推断。冻结官方ETTh1脚本却显式设置seq_len96、pred_len96，并由`Dataset_ETT_hour.__len__`计算8640-96-96+1=8449，插补损失只读取batch_x。公开论文表格与这个固定脚本不能直接视为完全相同的最终数据加载设置。[论文附录A.1](https://arxiv.org/html/2602.21043#A1)、[冻结官方ETTh1脚本](https://github.com/Oppenheimerdinger/T1/blob/823b76aab57a2e60eb5029caab06fdfec8b19256/scripts/imputation/T1_ETTh1.sh)、[冻结官方数据加载器](https://github.com/Oppenheimerdinger/T1/blob/823b76aab57a2e60eb5029caab06fdfec8b19256/data_provider/data_loader.py)。

这不改变第3节的核查结果：目前跑出来的T1 P4对照使用本项目的共同迭代器，没有多获得额外未来修复监督。

## 6. 后续应建立的统一下游对照

为了直接检验即插即用修复模块，可复用各自Stage1权重，对双方同时冻结修复器并保持eval；使用同一预测输入补齐规则、同一原PatchTST结构及初始化，从头按相同纯MSE、100轮、batch128、Adam lr1e-4、固定验证MAE与共享测试掩码训练预测头。该对照让收益归因更明确。若需要联合更新修复器，应另列双方采用共同下游目标与预算的联合训练对照，方法特有的修复保留项单独做消融。

若改用完整训练分区的独立96点插补窗口，应同时用于E23和T1并保留末批，以纳入最后96点。训练分区内的数值可以参加修复训练；单样本的推理仍只接受96点可见历史。现有Stage1权重不会因修改窗口说明而自动成为全覆盖训练版本，必须单独记录新协议和新增训练成本。
