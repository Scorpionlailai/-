# Weather v115：扩大 Stage 1 全窗口校准容量

## 依据与目标

用户已授权持续迭代 Weather 修复；预测为后续事项。当前正式 v107 的20组测试全96 MSE/MAE为0.0422470674/0.0540059649，近32为0.0423407986/0.0546617391；MAE仍落后SAITS。

固定训练子集的CPU筛查中，256维校准层在全验证集取得MSE0.1634846385、MAE0.0868561711，较相同条件64维分别改善7.86%和2.12%。筛查只用于选择候选，正式训练不复用筛查权重。

## 固定设计

- 独立源码副本；v107/v108正在使用的文件不修改。
- 三专家及点级特征维度仍64，复用同场景Weather-v79粗修复权重和历史库。
- 仅全窗口GlobalDenseRefiner从64扩到256；4个注意力头、2层、FFN=2倍宽度、局部核7、原上下文边界引导门保留。
- 旧均值投影器23682参数可训练，256维校准层1185066参数可训练，共1208748；其余专家及历史库冻结。
- 新输出层及门层零初始化，初始修复必须与粗修复父模型完全一致。
- Stage 1损失为全96缺失坐标全局标准化MAE + 0.25×近32缺失坐标MAE，Adam lr=1e-3、batch128、FP32、seed2023，训练满100轮。
- 保留原逐轮训练缺失掩码；固定验证5175窗口，独立保存验证MAE主选模与MSE次选模权重。
- 正式测试原20组固定掩码，各10444窗口，记录均值、掩码标准差、显存与完整Stage1成本（含复用粗修复训练）。
- 不自动训练Stage2。原PatchTST参数35427、初始化SHA、查询归一化统计保持原协议；后续若运行Stage2，修复器完全冻结且预测纯MSE。
- GPU1空闲时运行，与GPU0上的v108并行。

## 实施与验证

1. 建立独立源码快照和运行根目录，记录继承来源。
2. 先写并运行失败测试，再实现global_dense_width设置（默认64，允许64/128/256），贯通模型构造及检查点身份。
3. 验证默认64数值/参数一致、256零初始化保持父输出、可见/无效位置不变、缺失位置梯度有限、不同宽度检查点拒绝加载。
4. 正式预检2个Weather验证窗口、历史状态严格匹配、实际参数数目、预测头初始化SHA；冻结源码与协议后启动。
5. 每5分钟检查训练状态、每10分钟汇报；全训练后仅评估锁定的两份检查点，更新正式比较与目标审计。

## 达标口径

全96和近32的MSE/MAE均超过同口径已复现基线，才称本协议修复最佳。当前已测E23最低MSE为v107；MAE最低为SAITS。上述单次训练和20掩码属于开发比较，不代表所有文献、数据集或训练种子上的普遍SOTA。

## 完成记录

正式100轮及两份20组修复评估已完成。MAE主选择为精炼24轮：全96 MSE/MAE0.0424758760/0.0431837104，近32为0.0426594148/0.0435136857。相对T1、SAITS四项均值及配对掩码95%区间均改善，但MSE仍高于v107，不能单独称全部版本最佳。完整Stage1父链176.226分钟，allocated20.062GiB。

其与64维v108的校准输出在固定验证上互补，后续v125锁定1:1并只共享一份粗修复，正式测试四项同时最佳。详见[最终报告](2026-10-09_Weather_v125_repair_goal_result.md)。
