## 2. v125完整构成

### 共享粗修复

保留Weather-v79/v97路线：64维三专家T/V先产生窗口证据，再交给H检索历史；一轮TV→H恢复。保留窗口CNN、变量时间签名、点级专家路由、8头候选读出、置信重叠聚合、近32点残差修复。H候选4个；V候选4个并使用原时间偏移。历史库、检索键、专家粗修复权重沿用同场景父检查点。

修复坐标保留鲁棒局部尺度`sqrt(visible_std² + 0.1²)`；预测接口使用原来的可见均值和标准差，二者不能混用。输出重新生成原16块长/8步长的patch接口。可见值不被修复覆盖。

### 两条不同容量的全窗口校准

同一份粗修复、路由与点级特征，分别输入64维v108校准路径和256维v115校准路径；**粗修复只计算一次，不复制两个完整修复器**。

每条路径保留原均值修正，并读取5C=105维输入：全局尺度粗修复、真实可见值、原观察掩码、可见边界建议差值、引导置信度。结构为输入线性映射、LayerNorm、核7局部卷积与变量混合、96点位置表示、2层4头Transformer（FFN为2倍宽度，dropout0.1）。输出受限全局残差及零初始化的上下文边界门控。

两条校准输出按固定0.5/0.5组合。比例来自测试前封存的9点固定验证搜索，按全96验证MAE选，要求MSE不退于MAE更好的父模型。组合只作用于隐藏有效且存在真实可见来源的位置；可见、无效和无来源位置保留原值。

两条校准共有**1,319,832个参数**，这个数字不包含共享粗修复的参数。比例是固定buffer；v125物化时没有新增优化器更新。它依赖两条已经完整训练的校准路径，不能描述为零训练成本。普通单校准加载器会拒绝此组合检查点，必须按专门配方构造模型。

## 3. 训练、选模和实验协议

- 数据：Weather，21变量，52696行、10分钟采样。原CSV SHA256为`34ee981d07313e51da2a50bb600072c8ae4a69cb4b0651f4cb93a069d7a2ba63`。
- 划分：train `[0,36887)`，validation `[36887,42157)`，test `[42157,52696)`；原训练集标准化、窗口与协议不变。
- 96点回溯、96点预测接口；缺失块起点率0.10、块长8、允许重叠。测试窗口实际平均缺失约**57.0068%**，不是10%。
- E23训练seed2023，原逐轮变化训练掩码；验证掩码seed2021，5175窗口。20组测试seed为2026100801至2026100820，每组10444窗口、无drop；各模型逐组SHA及计分坐标数完全一致。T1作者配置seed502，SAITS seed2023。
- 共同粗修复完整训练100轮；64维和256维校准各独立训练满100轮，总来源训练300轮。校准阶段冻结三专家及库、训练均值和校准层，batch128、FP32、Adam lr1e-3，目标为全96隐藏坐标MAE + 0.25×近32隐藏坐标MAE，均为全局标准化尺度。
- 两条路径按固定验证MAE分别选精炼第97、24轮；来源配对epoch分别176、103。v125沿用配对库元数据103，`best_refinement_epoch=0`表示组合阶段没有新增训练，不能误解为校准未训练。
- v125验证锁定1:1后，正式20组只运行一次；开发测试没有用于选比例、epoch、训练seed。固定验证全96 MSE/MAE为0.1922607737/0.0599336363，近32为0.1850195925/0.0599218786；这些不是测试成绩。
- manifest中的基础结构/粗阶段目标字段沿用父配置。两条实际校准训练的目标、资源和来源以明确的父选择记录及组合配方为准，不把基础字段`global_mse_v1`解读成校准阶段的实际目标。
- 原PatchTST预测头35427参数、初始化SHA `fbbe8cde92c6417f1b5f67db888e20437dae434709b9e2adc834ce91118f6561`不变。**本轮没有Stage2**；以后运行必须冻结完整组合修复器并eval，预测损失纯MSE。

## 4. 成本与核验

完整Stage1来源成本为共同粗修复7692.589秒 + 64维校准2795.378秒 + 256维校准2880.990秒 + 新组合验证/物化20.121秒 = **13389.077秒，223.151分钟**。这是实际父训练工作流成本去重求和，包含准备、验证、保存；不是一次连续冷启动墙钟，也不包含最终测试及其他失败筛查。两个独立校准曾并行运行，成本没有因此减半。

设备RTX5090，完整训练链峰值allocated/reserved为**20.062/30.041GiB**，主要由共同粗训练产生。均为进程PyTorch allocator峰值，不是整卡占用。v125训练成本和显存明显高于T1、SAITS，本轮只达到准确率目标。

实际预检：5175个验证窗口，共41批，粗修复恰好调用41次；共享实现与双模型原型四项差值均0；严格恢复通过；可见值、权重、记忆和检索键在正式评估前后不变。组合配方及来源SHA均绑定检查点。

针对性实现检查已通过：组合保护/恢复7项；连同宽度和引导门检查17项；Stage1资源范围4项。报告审查纠正了旧v115控制器把历史Stage2资源计入Stage1的问题，仅修正报告和标签，旧表已归档，训练与修复结果未重跑。
