# T1 冻结修复器：E23-v69 三场景对照

## 固定设置

- 数据：ETTh1，回溯 96，预测 96，训练集标准化；原始分割不变。
- 三场景：起点率/连续块长 0.10/8、0.20/8、0.10/16；各场景使用既有验证缺失和共享 20 组测试缺失，不新增/筛选测试位置。
- Stage1：复用对应场景作者配置训练、验证 MSE 选出的 T1 seed502 修复权重。
- Stage2：冻结全部修复参数、BatchNorm 缓冲状态，修复器 eval + no_grad；仅优化原有 PatchTST 预测头。
- 原有预测头：35,427 参数，与 E23-v69 初始权重 SHA 完全一致，seed2023；结构无改动。
- 损失：MSE + 0.2 MAE，与三组 E23-v69 逐一核实一致。
- 优化：Adam、lr1e-4、weight_decay0、batch128、100轮、FP32；每轮66次更新，训练动态缺失及顺序使用共同 seed2023。
- 验证 MAE 选模为主；同一训练轨迹额外保存验证 MSE 最优，仅作为附表。锁定后评测 20 组测试，不用测试选模。
- 用户要求 T1 保留原末尾复制补齐实现；E23 原记录为零补齐。这个接口差异会明示。

## 执行与验证

1. 隔离源代码，记录源文件和既有记录 SHA。
2. 单元验证冻结参数、缓冲状态、输入和监督分离；各场景 CUDA 预检一次预测头更新。
3. 顺序运行三组 Stage2，每轮核对修复器完整状态 SHA 不变；验证后保存并锁定 checkpoint。
4. 每组评测 20 个缺失位置，保留逐组和逐窗口误差，输出均值/标准差、共享位置配对差异。
5. 输出对照 CSV 和报告；旧联合训练作为补充，不能把本次差异全部归因于冻结。

## 资源与解释

- 同一 GPU：cuda:1 RTX5090，CPU线程4，顺序运行。
- 新 Stage2 命令实测全部准备、100轮训练、验证、保存耗时及 PyTorch allocator峰值显存；最终测试单独排除。
- 原 Stage1 时间/显存从既有测量提取，与新 Stage2 合成训练成本，并明确 Stage1 已复用；不宣称本次完整从头两阶段墙钟耗时。
- 修复训练和模型结构保留各自方法设定；E23-v69 已有结果用于对照，不重新训练、搜索或挑种子。
