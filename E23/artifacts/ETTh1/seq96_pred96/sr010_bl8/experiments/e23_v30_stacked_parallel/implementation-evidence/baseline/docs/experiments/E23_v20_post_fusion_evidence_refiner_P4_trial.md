# E23 v20: evidence-aware post-fusion latent refinement

Predeclared 2026-10-01, before training. Incumbent v12 ETTh1 P4 validation forecast MSE/MAE is `0.7454477286392869` / `0.5882120694703256`; selected test `0.4256128043003904` / `0.431006140719736`. The direct implicit prediction interface of v19 failed its validation gate, so this trial keeps **v12's explicit repair-to-PatchTST forecast interface**. It asks whether the fused H/V/T latent needs one contextual consistency step before its numerical decoder.

Retain the v12 H, V, T experts and candidate rules, shared `none/H/V/T` router, width-64 latent, decoder, observed-value clamp, original width-16 PatchTST encoder/head, fixed masks, and training losses. Add one post-router, pre-decoder factorized context block over the 12 patches and seven variables. It first attends across time within each variable, then across variables at each patch. Its input includes the routed latent and four observed-evidence features: visible fraction, `none` route weight, route entropy, and weighted disagreement among expert residuals. A learned scalar confidence gate and the missing fraction scale the context residual. The final residual projection is zero-initialized so the new block starts as the identity and cannot alter fully observed patches. It uses only the current lookback, original observation mask, and H/V/T evidence; no future labels or generated repair values enter its input. Explicit repair still hard-preserves observed coordinates.

Train fresh Stage 1 and Stage 2 for 100 epochs each using the locked ETTh1 P4 96→96 protocol, seed 2021, batch 128, width 64. Stage 1 selects earliest minimum fixed-validation hidden-coordinate repair MSE. Stage 2 uses `MSE + 0.2 MAE` and selects earliest minimum fixed-validation forecast MAE. Promote v20 only if validation forecast MAE is strictly below `0.5882120694703256` and MSE is no higher than `0.7454477286392869`. Replay the selected checkpoint, verify unchanged H state, and run a selected test only if this gate passes. One seed on repeatedly used ETTh1 validation remains exploratory.

## Result

Both fresh stages completed all 100 epochs. Stage 1 selected epoch 97 at hidden-coordinate validation repair MSE `106.64058830222997`, an improvement of `0.26637540207003` over v12. Stage 2 selected epoch 7 at validation forecast MSE `0.7510961967260659` and MAE `0.5933900603902043`, worse than v12 by `0.0056484680867790` MSE and `0.0051779909198787` MAE. Later validation MAE rose substantially (epoch 100: `0.61927838`); the predeclared selected checkpoint remains epoch 7. **V20 fails both forecast promotion conditions; v12 remains the selected E23 model.** No v20 test evaluation was run.

The selected Stage-2 checkpoint was reloaded and replayed over all 2,688 fixed-validation windows (1,806,336 future coordinates), exactly reproducing both metrics. The H retrieval key SHA-256 was `491f41d079269ea0611b37c2de710d778857c492eb88cc999a9f1129fbbd5cc0` before and after replay. The new block added 55,429 parameters. Its zero-initialized projection started at an identity mapping, and the post-fusion unit, E23 config, Stage-1 and Stage-2 integration tests passed (39); a real ETTh1 CUDA forward/backward pass was finite and gave nonzero gradient to the new output projection. Lower repair MSE did not imply a better forecast here. The result does not isolate whether excess capacity, the chosen evidence features, or the training schedule caused the forecast regression.
