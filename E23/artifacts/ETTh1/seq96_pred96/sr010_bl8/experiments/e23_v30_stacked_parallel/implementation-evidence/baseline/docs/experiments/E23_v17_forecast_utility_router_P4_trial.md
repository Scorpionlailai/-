# E23 v17: train-only forecast-utility supervision for the existing router

Predeclared 2026-10-01. Incumbent v12 validation forecast MSE/MAE is `0.7454477286392869` / `0.5882120694703256`; selected test is `0.4256128043003904` / `0.431006140719736`. V16's train-observed affine source alignment improved Stage-1 repair slightly but worsened both forecast metrics, so it was rejected. This trial keeps the **exact v12 architecture and selected Stage-1 checkpoint**. It changes only Stage-2 training of the existing H/V/T/none router; the original width-16 PatchTST predictor remains unchanged.

For the first 32 shuffled training windows of each 128-window Stage-2 batch, form four counterfactual histories from the already computed base latent and expert deltas: base (`none`), base + H, base + V, and base + T. An unavailable expert contributes zero; original observed values remain clamped in every counterfactual. Decode each history with the same repair decoder and run it through the same predictor under a no-gradient evaluation pass. Compute per-window, per-target-variable `MSE + 0.2 MAE` forecast loss for each option using **training future labels only**. Ignore options unavailable for the entire target variable. When the best option beats the second best by at least `0.05` in that loss, supervise the average router weight over damaged patches toward the best option with cross-entropy weight `0.05`. Unconfident examples add no auxiliary loss. The normal full-batch `MSE + 0.2 MAE` forecast loss remains the main objective and gradients still reach all existing trainable recovery and predictor components. The auxiliary teacher uses no validation/test labels and is absent at inference.

One read-only v12 **training-batch** diagnostic motivated this setting: best single-option counts among 896 target variables were `none=191`, `H=241`, `V=239`, `T=225`; the best-vs-second forecast-loss margin had median `0.0353` and 75th percentile `0.0841`. The current v12 route's largest average weight matched that single-option winner in `36.05%` of cases. Single-option performance is not the same as optimal patchwise mixing, so this auxiliary loss is a hypothesis, not an oracle guarantee.

Use the locked ETTh1 P4 protocol, seed 2021, batch 128, v12's selected Stage-1 H memory/key state and a fresh 100-epoch Stage 2 at learning rate `1e-4`. Select the earliest minimum fixed-validation forecast MAE; promote only if validation MAE is strictly below `0.5882120694703256` and validation MSE is at most `0.7454477286392869`. Replay the selected validation checkpoint and verify unchanged H state. If the gate fails, retain v12 and do not run v17 on test. As with earlier ETTh1 trials, a pass is exploratory until independent datasets and seeds confirm it.

## Result

Stage 2 completed all 100 epochs and selected epoch 86. This result rejects this particular single-option utility supervision setting on ETTh1 P4; it does not rule out all forecast-aware routing methods.
