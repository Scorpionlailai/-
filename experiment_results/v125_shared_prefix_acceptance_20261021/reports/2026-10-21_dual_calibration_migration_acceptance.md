# 双校准计算复用：成本边界与迁移验收

本轮是归档源码及成本诊断，没有新训练、测试或模型晋级。依据 commit b5a72ddbf66d9822f53efa96b07354e2bd120b4d 的 calibration_worker.py 与 policy.py，以及已验证的本机128步等价实验。

后两列是敏感性计算，不是PAMAP2加速实测。公式为每seed校准阶段占比乘以假定节省率，再平均。归档阶段时间包含验证，可能遗漏保存/恢复开销；本机40.49%测的是更新段，不能直接替代整段校准节省率。完整Stage1的实际收益仍需端到端计时。粗训练不变，推理路径本来就共享一次前缀，因此不能宣称推理加速或参数减少。

## 源码核验及未覆盖问题

1. 两分支数据迭代都是 train、batch128、epoch-1、seed2023，每轮85步；共同输入具备复用条件。
2. initialize_branch分别seed_all(model_seed)，继承自身coarse水平层；新分支初始化哈希须和归档一致。不可将Weather加载成品权重的短测称为PAMAP2原训练复现。
3. 每轮分别完整验证，以full96 MAE严格小于历史最佳选各自checkpoint。两分支最佳epoch可不同，融合须读取各自最佳；不可用联合平均MAE或最后epoch替换。
4. resume保存model、optimizer、retrieval EMA、RNG、epoch、steps和选模状态。共享流程必须保存两套优化器/RNG/最佳权重，并把共同batch游标作为原子状态。只保存一套全局RNG不足以恢复独立dropout轨迹。
5. 外部evaluate实现未在此执行源码子目录中归档，其是否消耗RNG尚未证实。验收时须包括验证前后随机状态；验证如消耗随机数，应在各分支自身流内匹配原行为，不能无依据强行回滚。
6. 当前Weather短测未覆盖PAMAP2原生有效标签、完整epoch选模及中断恢复。现有权重/Adam逐值相同证据只覆盖已执行范围。
