# E24 实验规范 v1

日期：2026-10-07。适用于以封存 E23-v79 为起点的后续实验。本文件是正式比较的执行依据；机器可读设置见 `configs/experiment_protocol_v1.json`。当前仅进行目录迁移、文档和已有权重的验收，没有启动新训练。

## 1. 固定研究任务与比较对象

输入为带缺失的历史回溯窗口，输出未来序列。主要目标是缺失历史条件下的预测准确性，同时单独评价修复质量。默认回溯 96 点、预测 96 点、多变量预测全部变量；缺失只作用于输入历史，未来目标保持完整。

两类基线分开汇报：

- **修复器 + 公共预测器**：E24、T1、SAITS、BRITS。它们的 Stage2 必须使用同一预测器和下述公共训练配方，修复器全部冻结。
- **原生缺失预测模型**：CRIB、CoIFNet、BiTGraph、ChannelTokenFormer、S4M。保留作者原生预测架构、损失和训练配置；没有修复器/Stage2 的模型记为 N/A，不能人为把整个原生模型冻结。不得把这类对照称为公共预测头控制实验。

基线模型结构、Stage1 参数、优化器及早停优先采用作者公开的数据集对应配置；未公开则使用作者基础配置或官方示例，明确标记来源。回溯长度、预测长度、数据切分和缺失场景服从公共任务。ETTh1 的配置已经保存；其他数据集必须逐项锁定作者配置，不能把 ETTh1 配置默认为它们的论文最优配置。

## 2. 数据划分、标准化与信息边界

1. 每个数据集必须有独立 manifest：CSV SHA-256、变量列表/顺序、时间频率、总行数、train/validation/test 精确半开区间、窗口起点、窗口数和是否舍弃尾批。
2. 按时间切分。窗口未来目标不能跨入另一划分；允许读取切分边界前历史时，所有模型遵守同一规则并在 manifest 中声明。
3. 全局均值和标准差仅用训练段拟合，预测及修复 MSE/MAE统一在该训练标准化尺度计算。局部 query mean/std 仅从当前可见历史计算；隐藏真值只能作修复监督或离线诊断，不能作输入、统计量、检索 query 或候选来源。
4. H 原型库仅由训练历史中的真实可见信息构建。不得用 validation/test 更新原型、关系、统计或检索编码器；修复值不能作为真实观测写库。
5. 新数据集从头训练 Stage1/Stage2。默认不把 ETTh1 权重当作额外预训练；迁移权重实验另立协议和结果表。
6. 继承 ETTh1 的划分为 `[0,8640)` / `[8640,11520)` / `[11520,14400)`，7 变量。旧正式验证/测试口径为每组 2688 窗口；训练每轮 66 个 batch。其他数据集先锁定统一窗口范围，正式验证/测试建议保留全部合法窗口，不能模型间各自截断。与旧 ETTh1 的 2688 口径不同的结果另立新协议 ID。

## 3. 缺失场景与随机位置

块起点率不是最终点缺失率。采用现有 variable-wise 连续块生成器、允许块重叠；所有模型共用 generator 版本和相同原始 mask，记录观测/缺失语义及 SHA。

| 场景 | 块起点率 | 块长 | 旧 ETTh1 20 组实际平均缺失率 |
|---|---:|---:|---:|
| sr010_bl8 | 0.10 | 8 | 57.275731% |
| sr015_bl8 | 0.15 | 8 | 72.925184% |
| sr020_bl8 | 0.20 | 8 | 83.506023% |
| sr010_bl16 | 0.10 | 16 | 81.938811% |

实际缺失率随数据长度、位置和重叠变化，上表不能直接套到其他数据集。0.20/8 与 0.10/16 缺失率接近但不相等，不能把差异完全解释为块长的因果效应。

- 训练：每轮动态产生缺失位置，轮次/种子/采样顺序可复现；同一数据集、场景和配对 seed 的模型使用同一生成规则。
- 验证：一套固定位置，所有模型共享；仅依据这套验证集选 checkpoint。
- 正式测试：每个选定权重测试同一套 **20 组缺失位置**。一组覆盖全部测试窗口，不是一条样本，也不是一次训练。未来目标完全相同，不缺失。
- 原开发库种子 `2026100401..2026100420`、2026-10-07 确认库种子 `2026100701..2026100720` 都已公开，只可作回归/探索。不能再称为未见确认集。
- 后续确认实验必须在候选/权重和配置锁定后使用另一套预先封存的 20 组位置，记录何时锁定与何时查看。测试结果不用于选 checkpoint、搜索 seed 或反复选择正式模型。
- 默认每场景从头训练。用同一权重测试不同缺失参数属于跨场景泛化，必须另表说明，不能和按场景重训混排。

## 4. E24 Stage1 基础配方

| 项目 | 固定起点 |
|---|---|
| 结构 | E23-v79；D64、单轮 T→V→H、修复 P16/S8 |
| 优化器 / 精度 | Adam / FP32，weight decay 0 |
| epochs / batch / learning rate | 100 / 128 / 0.001，固定学习率，无早停 |
| 主要修复损失 | 训练标准化尺度上的缺失坐标 MSE（global_mse_v1） |
| 附加修复项 | 0.1 retrieval loss；recent_mean_v2：最近32点 level 权重1、trend权重0 |
| specialist exposure | 0.2 |
| 选模 | 固定验证集全窗口缺失坐标 global MSE 最小 |
| 辅助预测监督 | none；不继承 v76/v77 的辅助预测头或长缺失结构项 |

Stage1 是主要允许迭代的部分。改结构、损失、轮数或检索政策须创建新实验 ID、记录父版与唯一/全部差异，并保持 Stage2 不变。v79 的上述设置是基准，改过的设置不能继续标为“原 v79”。

修复退步不自动淘汰预测改进；若主张同时超过 T1，必须用同一模型/权重逐项提供证据。全窗口修复、最近32点修复、预测各自独立判定，不能用一种指标代替另一种。

## 5. Stage2 强制冻结规则

**适用于全部“修复器 + 公共预测器”对照，不允许联合训练、慢更新、只冻前端或在接口后新增可训练修复层。**

- 所有修复器参数 `requires_grad=False`，不出现在 optimizer 的参数组中，修复梯度为空。
- 每次切换训练模式后，整个修复器重新置为 `eval()`，包括 Dropout、BatchNorm 的运行均值/方差等缓冲。
- 原型库、检索编码器/keys、EMA、关系状态、校准参数及数据统计全部只读。
- Stage2 初始化、每轮结束、选定 checkpoint 和测试前后核对修复参数/缓冲/历史库/检索状态哈希或逐位一致性；任一变化使该次运行不符合规范。
- 原始可见坐标严格保留原值，输入 mask 的可见性不得因修复而变为“真实已观测”。
- 仅更新公共预测头；不加入 repair retention、修复正则、辅助预测头、forecast mixer、预测残差器或隐式替代接口。

| 项目 | 公共配置 |
|---|---|
| 预测损失 | **纯 forecast MSE**，全部未来96点×变量，不加 MAE/分段权重 |
| optimizer | Adam，learning rate 1e-4，weight decay 0 |
| epochs / batch / precision | **100 / 128 / FP32**，无早停，固定学习率 |
| 初始化 | 同一配对训练 seed、同一预测头构造序列，初始参数 SHA 必须一致 |
| 预测头结构 | PatchTST：P16/S8、D16、4 heads、FF128、3 encoder layers、dropout 0.3、fc_dropout 0.3、head/attn dropout 0 |
| 主 checkpoint | 固定验证 **MAE** 最小；并列保留先到达者 |
| 次 checkpoint | 同一100轮轨迹按验证 MSE 保存，明确作为次要结果，不能主表逐模型挑更好的一版 |
| 更新预算 | 同一数据集模型间窗口数、batch数、optimizer steps完全相同；ETTh1 6600次 |
| 修复接口 | 显式恢复后接原公共预测器；E24 `zero_invalid_v1`，T1 保留作者/现有 replicate-last 补齐，差异注明 |

改变预测头的研究另立协议 ID，所有插补基线重新匹配该预测头，不能并入本主表。新变量数下允许必要的维度适配，但必须跨模型一致，核对 head 参数/初始化及输出形状。

E24 正式入口 `python -m integrations.e24.run` 自动添加上述冻结/纯MSE参数，并拒绝 joint、混合损失、额外 mixer 等参数。底层 `integrations.e23` 和历史基线脚本为继承/兼容代码，**直接调用不等于符合本规范**；正式记录还必须通过状态、损失、预算及 head 身份核验。

## 6. 随机种子与统计层次

- 封存回归：E23-v79 Stage1/2 seed=2023；T1 Stage1 seed=502，公共 Stage2 seed=2023。这是一份模型对多组位置的结果，不是多训练种子结论。
- 单轮开发：固定 seed=2023，不按测试结果挑 seed；基线保留已锁定作者配方和声明的 seed。
- 正式多种子扩展采用已有预定列表 **102、202、302、402、502**，在开始该阶段前锁定执行矩阵。完整模型稳定性要求每个模型、数据集、场景、seed 从头训练全部阶段；只重复预测头必须写“Stage2 初始化重复”，不能称为五次完整训练。当前暂停状态不会启动这些训练。
- 计算 `m[s,j]`：训练种子 s、测试mask j 的指标。先对20组位置求每seed均值，再对seed求总均值；报告训练seed样本标准差 ddof=1，另报位置标准差，二者不能混用。
- 配对比较共享seed、mask和未来目标，报告 MSE/MAE 差值、逐组胜出数量。正式区间可对训练seed和mask两个轴分别做10000次配对 bootstrap，固定分析seed并保存；不能把5×20单元当成100个独立数据集/独立未来样本。

## 7. 必报准确性与修复指标

每份正式结果至少含：

1. 全局预测 MSE、MAE：全部未来预测坐标，训练标准化单位。
2. Stage1 选定修复器的全历史96点缺失坐标 MSE、MAE。
3. 同一修复器最近32点缺失坐标 MSE、MAE，含每组 hidden_coordinates。没有缺失坐标时记 N/A，不能记0。
4. 预测主表为20组测试均值。修复正式对照也应在相同20组测试位置计算并汇总；固定验证诊断必须标 `split=validation`，不得填入测试修复列。跨组坐标数不等时同时保存每组指标/计数和全坐标加权汇总，主表明确使用哪种方式。
5. Stage2后再核对修复结果和状态应与冻结的Stage1一致。全窗口修复指只算缺失坐标，不能用保留的可见值稀释误差。
6. DRR仅当每数据集/场景都有同口径 Clean、Missing 公共预测器参考时计算。Clean与Missing亦使用同一头、优化配置、seed和未来目标；分母<=0记N/A。Clean是训练参考，不是理论下界。

现有 v79 修复表只有固定验证诊断，尚未补齐20组测试修复；E24不能把这些旧诊断当作完成的测试修复成绩。

## 8. 资源、计时与监测

- 记录物理 GPU 名称/UUID、PyTorch/CUDA/Python、精度、batch、CPU线程；默认现有 RTX5090 GPU1，同卡顺序执行，避免其他本任务训练并行。
- 每阶段训练 wall time 包含训练期间验证及保存。完整两阶段成本包含命令入口/导入、数据与原型准备、全部训练、验证、保存及结束报告，排除最终测试；分别记录阶段时间和额外开销，不重复计数。
- 缓存Stage1 + 新Stage2必须单独标明缓存来源及原计时，不称“本轮完整实测”。多数据集从头正式重训优先测完整流程。
- 训练峰值显存：每阶段 `max_memory_allocated` 与 `max_memory_reserved`，单位GiB；取流程最大值。同时可补 `nvidia-smi` 进程显存，但不替代allocator指标、不当作整卡峰值。
- 测试耗时/推理峰值单独记。OOM减batch须登记新配置，公共Stage2对照重新对齐预算和batch，不悄悄覆盖。
- 获得训练授权后每 **300秒**检查日志/进程并报告阶段、轮次及异常。暂停后停止监测和自动启动；不擅自恢复。

## 9. 产物、验收和协议变更

推荐路径：`artifacts/<dataset>/seq96_pred96/<scene>/<experiment_id>/seed_<seed>/<model>/`，下设 `stage1/`、`stage2/`、`evaluation/`、`resources/`。

每个实验保存 plan、协议ID、父模型、源码/config/CSV/mask SHA、作者revision、seed、实际epochs/steps、各checkpoint SHA、Stage1→Stage2父权重SHA、冻结校验、head初始SHA、主/次选记录、逐mask指标、完整时间与显存sidecar、汇总CSV及失败日志。结果必须能追溯到同一checkpoint，不能跨版本拼接预测与修复赢家。

启动前依次验收：数据/切分 → mask身份 → 头初始化匹配 → optimizer只含head → 修复全状态冻结 → 全MSE → 选模只用验证 → 100轮实际更新预算 → 资源计时。未经这些核验的结果标 exploratory，不能直接作为协议v1正式结果。

修改窗口、预测长度、公共头、Stage2损失/冻结政策、mask算法、split或主选指标均创建新协议版本和独立对照表。修改Stage1仅创建新的模型/实验ID，保留本规范固定项。所有负结果和中断记录保留。
